# 8788 独立账号登录

## 入口与格式

后台 `/dola` →「账号登录入池」。仅后台所在电脑的回环连接可用，且管理员需有 `dola:import` 权限。每批 1–20 行、最多 32 KiB；先点「检查格式，不启动登录」可只做本地格式校验，不分配编号、不启动浏览器、不访问上游。

自动识别以下格式，第一段永远是账号标注邮箱：

```text
alice@example.com|示例密码
alice@example.com----示例密码----recovery@example.com
alice@example.com----示例密码----no----https://gapi.mailsapi.com/google/login?uid=示例标识
alice@example.com----示例密码----recovery@example.com----https://codes.example.com/示例接口
```

示例不是可用凭据。主邮箱规范化大小写并去掉 `\@` 的反斜杠；密码不裁剪，最多 1,024 字符；链接最多 8,192 字符。三段格式第三段必须是恢复邮箱。四段中的 `no` 仅配合白名单 Google 链接；其他第四段默认必须是公网域名 HTTPS 验证码接口，不能用登录链接冒充。指定公网 IP、HTTP 或自定义端口可通过下述服务路径白名单启用。

正式创建批次时，`dola_login_profiles` 为主邮箱预留永久递增编号 `A01`、`A02`…，显示为 `[A01]`。重复导入同一主邮箱不重新编号；取消批次也不回收已预留编号。历史账号不批量改名、不迁移；通过新入口核验入池后，账号列表显示编号和导入的主邮箱，而非辅助邮箱或昵称。

## 三种登录方式

1. **Google 密码登录**：在该账号独立浏览器中访问 Dola 并进入 Google。只在确认为 `accounts.google.com` 的邮箱、密码、恢复邮箱、邮件验证码步骤填写；这些步骤每类最多一次。验证器动态码（TOTP）使用独立的有限刷新流程，见下文。
2. **Google 已登录链接**：只接受指定主机、`/google/login` 路径和唯一非空 `uid` 参数，在同一独立代理窗口访问一次。不会向该第三方站点填写主邮箱、密码或恢复邮箱。Google Cookie/页面只作为开始 OAuth 的线索，不视为身份认证成功；最终仍核验 Google OIDC 邮箱、实际 Dola token 交换、会话绑定和在线 Dola 身份。不信任该第三方服务时请选择手动登录。
3. **独立窗口手动登录**：切换模式后，每行仅填标注邮箱，不填密码。打开全新的普通 Chrome 临时窗口（不是 Playwright 自动化启动器），自行选择手机号或邮箱登录 Dola。系统不自动填写或点击 Google 登录步骤，只通过 CDP 读取 Dola 回调后的会话并做真实身份核验；已有账号还必须与原 `sec_user_id` 一致。标注邮箱不等于已验证的上游绑定邮箱。窗口关闭或取消批次后，临时浏览器目录会清理。

浏览器位于后台所在的 Mac，不是 Windows WebView2，也不使用虚拟机的 D 盘路径。沿用账号原代理；新账号使用现有 IPWeb 配置分配的固定会话。代理检查失败即停止，不回退直连。

Google 阿拉伯语界面按明确的输入框及“下一步/继续/验证”语义识别；未知 RTL、多个匹配按钮、图形验证码、浏览器限制或未识别的安全步骤一律转人工，不猜左侧按钮、不绕过验证。自动登录等待通常最多 5 分钟；安全暂停最多 10 分钟，反复点击检查不会续期，超时清空整批剩余凭据。

## 登录窗口停住时

后台会显示最后执行阶段：检查代理 → 打开 Dola → 点击登录入口 → 点击 Google 登录 → 等待跳转 → 填写邮箱/密码 → 核验身份与 Dola 会话。窗口关闭、Google明确拒绝凭据、身份不一致分别显示，不把所有失败都归为密码错误。

Dola 首页可能先出现骨架，再显示“登录”及“Google 登录”按钮。入口过程共享最多120秒就绪等待，不重复点击或刷新；Google 来源已确认但表单/正文尚未就绪时，再给最多15秒加载窗口。明确出现验证码或安全步骤则立即暂停，不能保证免验证。

如果批次已结束或超时，自动填写凭据已经清除；单独留着一个 Google 邮箱页不会恢复自动登录。请刷新后台，选择自动识别模式，重新提交一个账号测试。手动登录模式本来就不会自动填写。

2026-09-21 通过原 IPWeb 的空白浏览器已实测入口自动到达 Google 邮箱页（约53秒），没有填真实凭据。该测试窗口已关闭；完整账号登录仍待新批次验收。

如果页面显示“此浏览器或应用可能不安全”，这是 Google 拒绝自动化浏览器的安全策略，不是输入速度或按钮选择问题。系统会标记为 `browser_blocked`、暂停本批并清除密码；不会通过伪装浏览器、关闭自动化标记、换代理或循环重试绕过。应改用官方支持的 OAuth 授权，或在本人控制的受支持常规浏览器中手动完成登录后再做身份回调核验。

注意：当前手头的 Dola API 说明只提供视频任务 Bearer Token 接口，不是登录 OAuth 文档。要实现官方 OAuth，必须由 Dola 提供或授权 OAuth client、精确回调 URI、scope 以及把授权结果绑定到 Dola 会话的正式接口；Google 自己的 OAuth client 只能验证 Google 用户，不能直接登录 Dola。

## 邮件验证码接口边界

只在明确识别的 Google 邮件验证码步骤发送一次无账号 Cookie、无 Authorization、无账号请求体的 GET；默认 HTTPS，其他端点须通过下述白名单。接口需返回 `text/plain` 或 `application/json`，最多 32 KiB，总超时最多 10 秒，禁止重定向。所有 DNS 结果须为公网地址，连接固定到已检查地址；HTTPS 保留 TLS 证书校验，显式公网 IPv4 不进行 DNS 解析。

接受纯 6 位或 8 位数字，或仅含 `otp` / `verification_code` / `code` 的简单 JSON，也允许这些字段位于 `data` 对象。复杂接口响应、多个不同验证码、HTML、图片、CAPTCHA、内网地址均拒绝，并交给用户手动处理。此服务端邮件接口请求不携带浏览器会话；Google/Dola 登录流始终使用账号代理。

## 验证器动态码（TOTP）

- 只在精确 Google 来源、`/challenge/totp` 路径、Google Authenticator 明确文案及唯一 `totpPin` 输入框共同确认时自动处理；邮件、短信、备用码、通行密钥和图形验证码不混用。
- 必须在同一个窗口完成过本次主邮箱提交，并在取码前后及慢速填写期间核对页面显示的完整邮箱；切换账号、离开 Google、出现多个 Google 窗口或未知验证步骤时停止并转人工。
- 取码服务接受纯 6 位数字，或保守的 JSON 对象适配：`code/otp/totp/token/pin/verification_code`，允许 `data/result` 最多六层包装及明确成功的状态字段。保留前导零；拒绝错误响应、重复/冲突验证码、任意文本数字提取和不明结构。未对真实服务响应做过验收，不能保证任意供应商格式都适配。
- 最多取码 **3 次**、提交 **2 个不同码**，刷新间隔至少 **15 秒**，整个 TOTP 阶段最多 **90 秒**；只有页面明确拒绝本程序刚提交的码才允许刷新。相同码不重复提交；页面未确认、接口失败或次数用尽时交给人工，不无限重试。
- 不处理用户/其他流程已填错的码，不从邮件 OTP 隐式切换到 TOTP 复用服务；取消或转人工即清空取码地址及码值。动态码通过不等于入池，仍要求原有 Google 身份、OAuth 回调绑定和在线 Dola 会话核验。
- 后台进度显示“已提交等待确认 / 等待刷新 / 接口仍返回相同码”；失败时解释原因并暂停后续账号。

## 取码服务路径白名单

环境变量 `DOLA_LOGIN_OTP_ENDPOINT_ALLOWLIST` 接受以逗号或换行分隔的 **完整来源 + 目录前缀**，目录必须以 `/` 结尾，不得包含账号秘密、查询参数或通配符。未配置时继续拒绝 HTTP、IP 字面量和非标准端口。

示例（只是配置语法，不是对示例服务的信任或连通性保证）：

```bash
DOLA_LOGIN_OTP_ENDPOINT_ALLOWLIST='http://93.184.216.34:8000/2fa/' node server/index.js
```

只允许同一协议、主机、端口以及指定目录下的请求；默认公网域名 HTTPS:443 仍可用。白名单不能覆盖内网/保留地址、重定向、凭据化 URL、路径穿越、登录页面和图形验证码资源禁令。导入、浏览器驱动、取码器共用校验规则。

**HTTP 会明文传输链接中的秘密与返回验证码，优先使用 HTTPS。** 路径白名单只是限制请求目标，不代表第三方服务可信。取码接口使用后台独立无会话 HTTP(S) 请求，不携带 Google/Dola Cookie，也不继承浏览器 IPWeb；浏览器登录链路仍强制原代理且不回退直连。

变量属于后台进程的启动配置，直接使用另一个不带该变量的启动命令会恢复默认严格限制；不要把完整账号取码链接写入启动配置。

## 存储与安全边界

新登录会话的受限 Cookie 与 localStorage 备份采用 AES-256-GCM，默认目录：

```text
~/Library/Application Support/DolaLogin/encrypted-sessions
```

目录权限 `0700`，随机密钥和账号加密文件 `0600`，文件名为邮箱摘要，认证附加数据绑定邮箱与原代理。最多复用 7 天，复用时仍在线检查会话和原身份。只保存允许的 Dola/Google 域，不保存第三方登录服务 Cookie，不保存输入密码、恢复邮箱或验证码链接。

旧会话目录只兼容读取，不自动移动、覆盖或删除；仅不存在新加密记录时，自动模式才允许读取旧缓存。新记录损坏、过期或代理不匹配时停止自动复用，不回退旧明文缓存、不自动重新输入密码。需要重新登录可主动选择全新的手动窗口，仍须通过原 Dola 身份核验。

**加密范围是新增的独立会话备份，不是整个号池数据库。** 既有 `admin.db` 仍使用原 Cookie 字段供生成器使用，本次未迁移为加密数据库；备份同样含敏感数据，应保持私有权限。密钥与密文位于同一系统用户下，不能抵抗该系统用户被攻破，不能称为 Keychain/硬件级隔离。

## 验收边界

格式、编号、权限、取消与超时、缓存加解密、代理绑定、SSRF 防护和浏览器状态机使用隔离测试验证；界面以纯模拟账号验证。没有使用真实第三方链接、真实验证码 API 或新 Google 账号做端到端登录；真实页面变化仍可能进入人工步骤。不保证免验证，也不代表视频生成成功率达到任何目标。
